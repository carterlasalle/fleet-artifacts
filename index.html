The method, and the mistake it exists to avoid

Both of these are https://… in the source, and a regex cannot tell them apart:

referencedoes the browser fetch it to DRAW the page? counts as an offender?
<img src>, <script src>, <link rel=stylesheet>, CSS @import, style url() yes — a fail here breaks the page YES
<a href> to a source URL no — only if the reader clicks NO

This tool stops reading the source for the verdict. It launches Chrome with every hostname unresolvable and no proxy, loads the page, and reads back what the browser actually tried to fetch and what came back empty (responseStatus:0, transferSize:0). A page is broken only when a subresource the page needed succeeded with the network up and was denied with it down.

What would falsify this

  • A control page carrying one remote <script src> must be found BROKEN — and it is, in the self-test, on every run.
  • A page with no remote anything must be found CLEAN — and it is; that is the negative control, and without it "found nothing" would be indistinguishable from "looked at nothing".
  • The light/dark pair must disagree on the network itself. If both runs report the asset loaded, the blackout failed and this page is worthless.
  • The logic self-test is sliced out of this build between its own marker comments, so the code under test and the test are the same bytes. The slice is then re-executed in a namespace holding nothing but re and json — on the first run it failed there with a NameError, which is the whole point of testing the bytes you ship rather than the ones you remember writing.

Honest limits

  • A citation is not proof it was followed. This page proves the cited URL did not load. It does not check the URL still resolves, or still says what the page claims. A dead citation passes this tool.
  • Rendering is not layout. Off-screen overflow and the 390px rule are a different measurement (see overflow390.py). This page fires no pixels judgment.
  • Excluded deliberately: /workshop/, /.selftest/, /node_modules/, /build/, /.output/, /downloads/, /shots/, /plug-proof/, /.browser-profile/, /test_fixtures/. Loop fixtures, browser-profile internals and build checkpoints are not shipped pages; leaving them out is a decision, not an accident.
  • The cache is disabled per launch, not per page. Two pages in one batch share a browser, so a URL fetched by the first page could in principle be served from memory for the second. The counts would not change; a per-page launch would.
  • 0 of 49 is the finding tonight. A clean sweep is a real result here and not a soft one — but it only covers the pages in the roots listed below.
